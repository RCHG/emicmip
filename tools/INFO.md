# rawcheck/

Answers three questions about the raw input4MIPs folders:

- (1) do folder names hold files consistent with their metadata?
- (2) are the updates the right (most recent) ones?
- (3) does each etc/*.toml uses the right `.nc` files?

It is an standalone, read-only, orthogonal to the tool and self-contained
(be careful there is no import from `lib/` but `build_raw_path` is a copy of
`lib/cmip_process.py::build_raw_path`,so keep that in mind). It uses `xarray`
but for the metadata only.

## How it was used

```bash
cp -r tools/rawcheck $HPCPERM/raw_emissions/cmip7/historical/
cd $HPCPERM/raw_emissions/cmip7/historical/rawcheck
make                         # every sibling folder
make REPO=~/emicmip      # ... plus which files etc/*_cmip7.toml read
make ONLY="BB4CMIP7 CEDS-CMIP" REPO=~/emicmip   # only folders starting so
make bytes REPO=...          # also byte-compare same-size files (slow)
```

Please check the output on screen or in `out/rawcheck.log` they are the same.
But it also creates two files with extra information:
- `out/inventory.csv` one row per file, all metadata
- `out/species_versions.csv` one row per file within its family: creation_date, 
   newest or not, identical/different vs the other folders,
   which config reads it.

**Property**: a symlink always counts as the file it points to, therefore metadata or size 
are read from the target, and the most recent version is attributed to the folder that
really holds the file (reads through a link are shown as `link->target`).

1. **Inventory & metadata** (goal 1), per folder: content by `source_id`
   (and how many were read as symlink), a FOLDER NAME vs CONTENT warning when a
   folder's own (non-symlink) files carry another version, storage of the main
   variable (dtype/compress), the 3 largest files, and per-file issues: filename
   version vs `source_id` attribute, species vs `variable_id`, symlinks to a
   file of another version or non-standard names (e.g. `_backup`) never read.
2. **Related folders**: folders sharing at least one species/subset/period
   (e.g. two versions of a dataset) are grouped automatically. For each group,
   first the **most recent version per species** (by the `creation_date`
   attribute, not the folder name) next to the folder the configs read, with a
   warning when a config reads an older file. Then, file by file, the same
   species/subset/period is identical (same file through a
   symlink, or byte-identical with `make bytes`), likely identical (same size
   and `tracking_id`), or different; plus what exists in only one folder.
3. **Per config** (with `REPO=`): species/periods found and MISSING (each
   period independently, as `cmip_preemis` does), scaling files, files used
   that have metadata issues, and files in its folders it never reads, each
   with the reason: SPECIES NOT IN CONFIG (candidate to add), SHADOWED (those
   years are read from another file/version), PERIOD MISMATCH (the file covers
   other years than the config's period, e.g. 197001-199912 vs 195001-199912),
   auxiliary (no period) or non-standard name. Section 2's "read" column is
   checked period by period.

# interp_check.py

## Motivation 
This was created to test the interpolation between years not provided on the 
ScenarioMIPs (that is providing data each 5 years). The tool implemented the 
recommented method of linear interplolatin, and here we have a validation of that
methodology. So `interpolate_years` is the interpolation of years missing in a raw
file, see the web page "Datasets". 

## Idea 
The idea is that on raw files that have every year, it drops the years inside a gap Y0->Y1,
rebuilds them by linear interpolation month by month (the same formula as `cdo intyear`) 
and compares them with the real ones, together with two naive baselines: *hold* (repeat Y0) and
*nearest* (closest of Y0/Y1). The tool is read-only; needs numpy, xarray (+cftime),
matplotlib, and cdo only for the specific option `--cdo`. 

## Method 

It finds the raw files from a `cmip_preemis` config, the same way
`cmip_preemis` does: give the toml and the species (as named in the toml;
`VOC01` matches `VOC01-alcohols`), and it looks in every group/subset that
lists them (`--groups` to restrict). `--files` takes explicit paths instead.

```bash
# ScenarioMIP: rebuild 2023-2024 from 2022 and 2025 (anthro, aviation, openburning)
python3 tools/interp_check.py etc/scenariomip-m_cmip7.toml SO2 NOx BC CO --cdo
# CEDS historical: 5-year gaps like 2025->2030, plus the COVID case
python3 tools/interp_check.py etc/historical_cmip7.toml SO2 NOx BC CO \
        --gaps 2000:2005 2005:2010 2010:2015 2015:2020 2018:2023 --sectors
```

- Default gaps (no `--gaps`): in the last period of each group, 2022:2025 if
those years are in the file, plus every 5-year window Y0:Y0+5 (Y0 a multiple
of 5) fully inside it. 

- With `--gaps`, the periods holding them are read. Per gap year it prints
the error of the annual total for each method and the mean monthly pattern
correlation of the linear one

- `--cdo` checks once per file that `cdo intyear` gives the same field (and the right year on its time axis). Output in
`outs/validation/<name>/` (default `interp_check_<toml>_<species>`): `interp_check.csv` (one row
per file/gap/year/month or annual/sector/method: totals in Tg, relative error,
pattern correlation, area-weighted normalised RMSE) and `interp_check.pdf`
(per file and gap: annual totals of the three methods vs real, monthly linear
vs real).
